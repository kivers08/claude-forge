- memory-v2 record foundation (D28, unit 1), record schema reshaped to D28.3's Anthropic-superset (SETTLED 2026-09-16): `plugins/forge/hooks/lib/memory.js`, a stdlib-only library to read/write per-agent memory records as markdown-with-frontmatter under `.claude/agent-memory/<plugin>-<agent>/`. A record is a strict superset of Claude Code's native memory format — `name`/`description` stay top-level (the Anthropic fields), and every forge operational/ranking field (`type`, `scope`, `id`, `tier`, `importance`, `created`, `lastUsed`, `uses`, `source`, `supersedes`) lives one level down under a nested `metadata:` block, with `type` drawn from Anthropic's four subject-types plus forge's own `decision` extension (`user | feedback | project | reference | decision`). Carries forward per-scope read isolation (D4), a strict `<plugin>-<scope>` charset that blocks path-traversal outside the memory root, bounded one-level nested-map / array serialization (both for the `metadata:` block and for preserved `extra` fields), full schema defaulting on write, a `supersedes` upsert that archives — never destroys — the old record, and a secret-redaction scrubber (PEM/API-key/token/`*_SECRET=` forms) run before every write (now scrubbing `name`, `description`, and every string in `metadata` in addition to the body and `extra`) that stamps a redaction caveat into any record it touched.
- `scripts/migrate-agent-memory.js`: a SAFE, additive, idempotent migration seed that stamps the memory-v2 schema onto existing `.claude/agent-memory/**` records — emitting the D28.3 `name`/`description` + `metadata:` shape and carrying a pre-existing `metadata.type` straight through per the D28.3 mapping (`user`/`feedback`/`project`/`reference` pass through unchanged; anything else defaults to `project`) — while preserving prior content and frontmatter and routing every write through the same secret scrubber; MEMORY.md indexes are left untouched. Per D28.2, memory migration is EXPLICIT (run deliberately at adoption), so this seed is NOT run as part of unit 1 — it does not auto-migrate this repo. The full archive-model adoption migration (move pristine originals to `_pre-migration/<scope>/`, never delete, human-invoked) is deferred to unit 8.

Per-record size caps, sharding, and any change to the `_archive/` supersede mechanism remain out of scope for this reshape as well.
